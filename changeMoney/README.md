This project compares two coin-change algorithms implemented in `moneyChange.h`:

## Algorithms

### Dynamic Programming

`giveChangeDP` calculates the minimum number of coins needed for every amount from `0` to the requested quantity. It then reconstructs the selected coins from the saved decisions. This algorithm produces an optimal solution when the amount can be formed. The denominations must be sorted before calling the function; sorting is not part of the function's complexity.

Let:

- `C` = number of coin denominations
- `Q` = amount of change

Complexity:

- Time: `O(CQ)` when the denominations are already sorted. Sorting separately costs `O(C log C)`.
- Space: `O(C)`.

### Greedy

`giveChangeGreedy` repeatedly selects the largest coin that fits the remaining amount. The denominations must be sorted in descending order before calling the function; sorting is not part of the function's complexity. It is efficient, but it does not always produce the minimum number of coins for arbitrary denominations.

If `K` is the number of coins selected and `v_min` is the smallest positive denomination, its complexity is:

- Time: `O(C + K)`, or `O(C + Q / v_min)` in the worst case. Sorting separately costs `O(C log C)`.
- Space: `O(C)`.

## How to compile and run from CMD

Open Command Prompt and move to the `changeMoney` folder. Then run the following commands:

Compile the program:
```cmd
g++ main.cpp -o moneyChange.exe
```

Run one test case:

```cmd
moneyChange.exe < input\input1.txt
```

Run all test cases:

```cmd
for %f in (input\*.txt) do moneyChange.exe < %f
```

Each input file contains the number of denominations, the denominations, the price, and the payment. The program calculates the change as:

```text
change = payment - price
```

It then prints the coin distribution generated by both algorithms.

## How to compile and run from Bash

Open a terminal and move to the `changeMoney` folder. Then run the following commands:

Compile the program:
```bash
g++ main.cpp -o moneyChange
```

Run one test case:

```bash
./moneyChange < input/input1.txt
```

Run all test cases:

```bash
for f in input/*.txt; do ./moneyChange < "$f"; done
```


## Test results

Tests were run on August 21, 2026 with `g++ 15.2.0` and C++17. Compilation succeeded and all four input files executed successfully.

| Test case | Change | Dynamic programming | Greedy |
| --- | ---: | ---: | ---: |
| `input1.txt` | 175 | 4 coins | 4 coins |
| `input2.txt` | 40 | 2 coins | 3 coins |
| `input3.txt` | 15 | 3 coins | 6 coins |
| `input4.txt` | 289 | 10 coins | 10 coins |
| `input5.txt` | 0 | 0 coins | 0 coins |
| `input6.txt` | 10 | 2 coins | 2 coins |
| `input7.txt` | -25 | Invalid | Invalid |

The results show that greedy is not always optimal. In `input2.txt` and `input3.txt`, dynamic programming uses fewer coins than greedy.
